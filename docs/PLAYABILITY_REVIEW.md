## 1. 재현한 현상과 확인된 원인

실제 브라우저 플레이 재현과 코드 실행 재현을 구분한다. 이번에 운영 페이지의 시작 화면은 브라우저로 확인했으나 사용자 농장을 플레이하거나 초기화하지 않았다. 아래 재현은 별도 Node/DOM 환경에서 원본 게임 코드를 실행한 결과다.

- **판매 후 당근 씨앗 선택**: 원본 게임의 실제 판매 이벤트 처리기를 실행했다. 인벤토리 `[손, 순무 씨앗×4, 순무×1, 당근 씨앗×3]`, 선택=손, 돈=235에서 순무 판매 후 돈=270, 선택=`seed_carrot`이 됐다. 바구니 처리기가 판매에도 `S.sel=i`를 설정하고, 삭제된 인벤토리 행의 숫자 인덱스를 재사용한 것이 직접 원인이다. 클릭 전파가 주원인이라는 증거는 없다.
- **튜토리얼 반복**: `tourEnd()`는 마지막 화면의 ‘다시 보지 않기’ 체크가 있을 때만 전역 플래그를 저장했다. 건너뛰기 자체의 농장별 상태는 저장하지 않았다.
- **시간 불일치**: 설정의 디지털 시각은 `fmtAt(0)`으로 기기 실제 시각을 출력했다. 게임 진행과 아날로그 시계는 `S.min`을 사용한다. 일반 취침 후 06:00, 기절 후 12:00은 기존에 구분되어 있다.
- **낮잠 과장 표기**: 실제 체력은 100으로 제한하면서 결과 문구는 고정 `+50`이었다.
- **잠긴 특별 매입 품목**: 특별 매입은 `unlocked('seed_'+작물)`을 호출하지만 원래 레벨 표는 작물 ID로 구성되어 있었다. 접두사를 정규화하지 않아 해금 검사를 통과했다.
- **미나리 심기 차단 경로**: 물칸 터치 처리기가 선택한 물작물 씨앗을 검사하지 않고 낚시·다슬기 처리로 먼저 반환했다. 씨앗·성장 데이터 자체는 이미 있었다. 일반 밭 재배 전체의 오류가 아니다.
- **멍석 그리기 누락 경로**: 멍석 이미지가 없을 때의 대체 그림은 있지만, 이미지가 로드된 경우 기본 그래픽 매핑에 `mat`이 없었다.
- **저장 누락**: `packO()`는 오브젝트의 종류·좌표·v만 저장했다. 과수 종류/나이, 물 준 날짜, 여러 칸 시설의 크기 등은 유실될 수 있었다. 과거에 이미 유실된 필드는 추측으로 복구하지 않았다.
- **친구 도움**: 방문 모드에서 `decide()`가 비활성화되고 `onTap()`은 이동만 허용한다. 실시간 저장은 별도 Google Apps Script 서버에 의존하며 서버 구현은 이 저장소에 없다.

## 3. 실제 검증 결과와 환경

- Node 24 + LinkeDOM에서 **실제 `index.html`의 스크립트 전체**를 실행했다. 별도로 재작성한 게임 로직을 테스트하지 않았다.
- 캔버스·이미지·오디오는 대체 객체, 시간·인터벌은 제어한다. 따라서 그림이 실제로 맞다는 증거가 아니다.
- `npm ci --ignore-scripts && npm test` — 24개 통과.
- 원본 판매 이벤트 재현: `{gold:270, held:'seed_carrot'}`. 수정본: `{gold:270, held:'hand'}`.
- 마지막 아이템 판매, 판매 전 선택한 씨앗 유지, 빠른 후속 입력 보호, 터치형 이벤트 모형 검사.
- 일반 작물 파종 → 물주기 → 실제 성장 콜백 → 수확 → 판매 → 정산 누적 → 다음 날 06:00.
- 미나리 파종 → 자동 수분 → 실제 성장 콜백 → 수확 및 후보 조건.
- 시설 목적지 변경·방향, 과수 수분 상태 저장·재로딩, 멍석 설치 저장, 시설 크기 저장.
- 건너뛰기/완료 저장, 새 농장 구분, 예전 저장의 돈·씨앗·작물 보존.
- 오전/오후 경계, 낮잠 96→100의 +4, 완료 가공품 없는 정산 문구, 상점 데이터/접기, 식당 필터/재료 표시.
- 4계절 × Lv1·3·10 조건에서 새 주문 후보 검사. **기존 채소는 계절 제한이 없는 코드**이므로 임의의 계절표를 만들지 않았다. 꽃은 실제 `sea` 필드 사용.
- `#test`는 이 게임 스크립트의 저장 키를 `farm-qa:`로 분리하고 마을 업로드를 막는다. 운영 `farm-save`를 읽거나 쓰지 않는 검사 통과.
- 일반 저장은 첫 변경 전 원문을 `farm-save-backup-playability-20261101`에 1회 보존한다.

## 4. 남은 미검증 / 구체적인 제한

- 로컬 수정본 주소를 테스트 브라우저로 열었으나 `ERR_CONNECTION_REFUSED`였다. 브라우저와 코드 실행 환경이 다른 곳에 있다. 운영 페이지를 수정본으로 간주해 검증하지 않았다.
- PC 브라우저의 실제 클릭·더블클릭, 브라우저 터치 에뮬레이션, iPhone/Android 실기기 **미검증**. Node의 `pointerType:touch` 이벤트는 모바일 브라우저 에뮬레이션도 아니다.
- 실제 사용자 저장 원문은 읽거나 변경하지 않았다. 기존 저장 검사는 분리된 합성 fixture다.
- 실제 이미지 로딩 후 UI 겹침, 작업 표식, 연기 위치, 모든 시설·고레벨·실온라인 방문, 외부 `../games/ph.js`와의 시각적 상호작용 미검증.
- 주문의 지급/수령/갱신 변경은 정책 결정 후 테스트를 추가해야 한다. 기존 완료 주문 자동 교체·보상 중복 없음은 아직 검증 완료가 아니다.
- 배포 전 별도 브라우저에서 수정본을 띄우고 `#test`로 위 흐름을 플레이하는 단계가 필요하다. 실제 농장 초기화로 대신하지 않는다.

## 5. 결정이 필요한 추천안

모든 수치는 **제안**이다. 구현 또는 확정된 값으로 취급하지 않는다.

### 먼저 결정할 3개

1. **주문**: 목표 달성 → ‘보상 받기’ → 지급과 동시에 다음 주문. 조건이 바뀐 기존 불가능 주문은 재료/진행을 소비하지 않고 해당 슬롯만 교체한다. 조건부로 가진 수확물만으로 납품 가능한 주문은 유지한다. 후보가 없으면 쉬는 슬롯을 표시한다. 지급과 새 주문을 하나의 저장 단위로 묶고 주문 ID별 수령 기록으로 중복 지급을 막는다.
2. **불멍**: 현재 약 1.2/초 → **0.2/초**, 벤치 0.15/초 권장. 게임 시간 추가 가속은 제거하고 일반 시간으로 진행. 60 회복에 실제 5분이 걸려 요리의 즉시 회복 의미를 유지한다. ‘초당 +0.2, 시간은 계속 흐름’을 표시한다. 실제 플레이 밸런스 검증 후 조정한다.
3. **밭 삭제**: 빈 밭만 삭제 가능, 확인 1회, 환급 없음. 심어진 밭은 ‘먼저 수확/뽑기’를 안내한다. 작물 손실을 동반하는 일괄 삭제는 우선 추가하지 않는다.
